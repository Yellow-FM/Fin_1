# Fin_1
# Общая структура

Приложение построено на основе библиотек Streamlit (интерфейс), Polars (быстрая обработка данных), Plotly (интерактивные графики) и SQLite (источник данных). Код разбит на логические блоки:
загрузка и кэширование исходных данных;
создание производных (вычисляемых) столбцов;
боковая панель с основными фильтрами;
основная область с метриками и пятью вкладками для разных видов анализа.
1. Загрузка данных и производные столбцы
Данные читаются из базы weather.db в Polars DataFrame. Функция load_data() кэшируется (@st.cache_data), чтобы не перечитывать БД при каждом изменении виджета.
После загрузки с помощью функции add_derived_columns() добавляются три новых поля:
temp_category – категория температуры:
"Холодно", если avg_temp < 10°C;
"Умеренно", если 10°C ≤ avg_temp ≤ 25°C;
"Жарко", если avg_temp > 25°C.
precip_level – уровень осадков:
"Без осадков" при total_precip == 0;
"Небольшие" при 0 < total_precip ≤ 5 мм;
"Сильные" при total_precip > 5 мм.
comfort_index – упрощённый индекс комфортности:
"Комфортно", если температура от 18 до 25°C включительно и скорость ветра менее 5 м/с;
"Дискомфортно" – в остальных случаях.
Эти поля доступны во всех разделах приложения.

2. Фильтры на боковой панели
Слева расположены два основных виджета:
Выбор города (st.selectbox) – определяет, для какого города отображается детальная информация.
Диапазон дат (st.date_input) – календарь с возможностью выбора начальной и конечной дат. Границы задаются минимальной и максимальной датами из всего набора данных.
Все последующие операции (кроме вкладки «Сравнение городов») фильтруют данные именно по выбранному городу и диапазону дат.

3. Вкладка «📋 Данные»
Отображает отфильтрованную таблицу с возможностью выбора столбцов через st.multiselect. По умолчанию выбраны:
date, avg_temp, total_precip, avg_wind, is_rainy;
производные столбцы: temp_category, precip_level, comfort_index.
Пользователь может самостоятельно включить/исключить любые поля. Таблица поддерживает сортировку по столбцам (через встроенные возможности st.dataframe). Постраничного просмотра нет, но высота таблицы ограничена 400 пикселями для удобной прокрутки.

4. Вкладка «📈 Распределения» (EDA)
Здесь выполняется разведочный анализ для выбранного города и периода. Пользователь выбирает показатель:
"avg_temp" – средняя температура;
"total_precip" – общее количество осадков;
"avg_wind" – средняя скорость ветра.
Для выбранного показателя строятся два графика (в колонках):
Гистограмма (px.histogram).
boxplots (px.box).
Под графиками выводится таблица с описательной статистикой (describe()), включающая среднее, стандартное отклонение, минимум, квартили и максимум.

5. Вкладка «🏙️ Сравнение городов»
Позволяет сравнивать погодные показатели между несколькими городами:
Виджет st.multiselect даёт выбрать любое количество городов из доступных (по умолчанию выбраны первые три).
Данные фильтруются по выбранному диапазону дат (общему, не только по ранее выбранному городу) и списку городов.
Выпадающий список выбирает метрику для сравнения (avg_temp, total_precip, avg_wind).
Строится столбчатая диаграмма (px.bar) со средними значениями метрики по каждому городу за указанный период.
Дополнительно выводится таблица со средними значениями.
Это позволяет быстро оценить, где было теплее, больше осадков или сильнее ветер.

6. Вкладка «⏳ Временные ряды»
Отображает динамику средней температуры во времени с простым прогнозом на основе скользящего среднего.
Пользователь может выбрать показатель (пока только средняя температура, но код легко расширить).
Слайдер st.slider задаёт окно скользящего среднего (от 2 до 30 дней, по умолчанию 7). SMA рассчитывается центрированно (center=True), чтобы линия не сдвигалась по времени.
На графике (go.Figure) отображаются:
фактическая линия (синяя, сплошная);
SMA-линия (пунктирная, другой цвет);
при необходимости – вертикальная линия с подписью «Сегодня», если текущий день попадает в выбранный диапазон дат.
Подпись поясняет, что пунктир – это скользящее среднее.
Таким образом, реализована задача «временные ряды и прогнозирование» – простой метод сглаживания, который позволяет увидеть тренд и сгладить шум.

7. Вкладка «⚠️ Аномалии»
Здесь под аномалией понимается день, в котором поле is_rainy равно 1 (дождливый день). Для выбранного города и периода выводятся:
количество таких дней;
таблица с полной информацией по этим дням.
Можно изменить критерий аномалии, отредактировав фильтр, но текущая реализация соответствует условию «дождливый день» из исходного датасета.
